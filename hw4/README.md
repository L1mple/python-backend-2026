# ДЗ 4 — Работа с базой данных и транзакциями

В этом задании добавил хранение данных в MySQL для API магазина из предыдущих домашних работ и реализовал скрипт для демонстрации различных уровней изоляции транзакций.

## 1. Работа с базой данных

Вместо хранения товаров и корзин в Python-словарях теперь используется MySQL 8.4 и SQLAlchemy ORM.

В базе созданы три таблицы:
- `items` — информация о товарах.
- `carts` — корзины пользователей.
- `cart_items` — товары в корзинах и их количество.

MySQL запускается через Docker Compose. Для хранения данных используется Docker volume, поэтому после перезапуска приложения товары и корзины сохраняются.

### Запуск

Из папки `hw4`:

```bash
docker compose up -d --build
```

После запуска API доступен по адресу http://localhost:8080/docs.

## 2. Демонстрация транзакций

В файле `transaction_demo.py` реализованы примеры аномалий, возникающих при параллельной работе с базой данных.

Для запуска:

```bash
docker compose exec shop-api python transaction_demo.py
```

Скрипт создаёт тестовую таблицу и выполняет операции в нескольких независимых транзакциях с разными уровнями изоляции.

Результаты:

| Уровень изоляции | Что проверяем | Результат |
|---|---|---|
| READ UNCOMMITTED | Dirty read | Незакоммиченное изменение видно (900) |
| READ COMMITTED | Dirty read | Незакоммиченное изменение не видно (100) |
| READ COMMITTED | Non-repeatable read | Значение меняется: 100 → 200 |
| REPEATABLE READ | Non-repeatable read | Значение не меняется: 100 → 100 |
| READ COMMITTED | Phantom read | Появляется новая строка: 0 → 1 |
| REPEATABLE READ | Phantom read | Новая строка не видна: 0 → 0 |
| SERIALIZABLE | Phantom read | Вставка блокируется до завершения читающей транзакции |

Все проверки прошли успешно.

### Особенность MySQL

В задании предлагается показать phantom read при `REPEATABLE READ`. Однако в MySQL с движком InnoDB обычные `SELECT` внутри транзакции используют один и тот же снимок данных (MVCC), поэтому в таком сценарии phantom read не возникает.

Поэтому дополнительно показал phantom read на уровне `READ COMMITTED`, а на `REPEATABLE READ` — его отсутствие.

На уровне `SERIALIZABLE` также показал, что конкурирующая вставка блокируется до завершения читающей транзакции.

Подробнее об уровнях изоляции MySQL: https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html
