# ДЗ4: база данных и транзакции

Магазин из HW2 хранит товары, корзины и их состав в PostgreSQL через SQLAlchemy.
Таблицы создаются при запуске приложения. У каждого запроса своя сессия и
транзакция: при успехе изменения сохраняются, при ошибке откатываются.
При добавлении товара строка корзины блокируется через `SELECT FOR UPDATE`,
чтобы параллельные запросы не теряли изменения количества.

## Запуск

Из корня репозитория:

```sh
docker compose -f hw4/docker-compose.yml up -d --build
```

API: http://localhost:8004/docs, метрики: http://localhost:8004/metrics.
База доступна на `127.0.0.1:7433`, имя БД, пользователь и пароль — `shop`.
Это локальные настройки для домашки. Данные PostgreSQL сохраняются в volume.
Порты отличаются от HW3, поэтому оба задания можно запустить одновременно.

Для запуска Python без Docker установите зависимости из
`hw2/hw/requirements.txt` и укажите `DATABASE_URL`.
Без этой переменной используется SQLite (`shop.db`), чтобы API и тесты
работали без отдельного сервера БД. Для примеров изоляции нужен PostgreSQL.

## Примеры транзакций

После запуска БД и установки зависимостей:

```sh
python hw4/transactions.py
```

Скрипт подключается к локальной БД из Compose. Он открывает два соединения
и выполняет действия транзакций по очереди, чтобы результат не зависел
от задержек или порядка выполнения потоков. Проверки сделаны через `assert`.
Для каждого запуска создаётся отдельная временная схема, которая удаляется
в конце. Таблицы магазина не затрагиваются.

| Пример | Уровень | Результат в PostgreSQL |
| --- | --- | --- |
| Dirty read | Read uncommitted | Нет: читатель видит 100, хотя писатель изменил значение на 200 без commit |
| Dirty read | Read committed | Нет: читатель также видит 100 |
| Повторное чтение строки | Read committed | 100 → 200 после commit другой транзакции |
| Повторное чтение строки | Repeatable read | 100 → 100 |
| Повторный подсчёт строк | Read committed | 1 → 2 после вставки и commit другой транзакции |
| Повторный подсчёт строк | Repeatable read | 1 → 1, фантомов нет |
| Повторный подсчёт строк | Serializable | 1 → 1, фантомов нет |
| Два дежурных одновременно уходят | Repeatable read | Оба читают, что дежурных двое, и уходят: остаётся 0 |
| Два дежурных одновременно уходят | Serializable | Одна транзакция отклонена с SQLSTATE 40001, остаётся 1 |

В условии предложено показать dirty read на Read uncommitted и фантомы на
Repeatable read. В PostgreSQL эти эффекты невозможны: Read uncommitted
работает как Read committed, а Repeatable read использует стабильный снимок.
Это описано в [документации PostgreSQL](https://www.postgresql.org/docs/15/transaction-iso.html).
Поэтому скрипт показывает фактическое поведение выбранной БД. Для сравнения
Repeatable read и Serializable добавлен пример с дежурными (write skew).
После ошибки сериализации повторяется вся транзакция: новая проверка видит
одного дежурного и не разрешает ему уйти.

Вывод проверенного запуска: [transaction_results.txt](transaction_results.txt).

## Тесты

Пример для PowerShell после установки зависимостей:

```powershell
$env:PYTHONPATH = "$PWD/hw2/hw"
$env:DATABASE_URL = 'postgresql+psycopg://shop:shop@127.0.0.1:7433/shop'
python -m pytest hw2/hw/test_homework2.py hw4 -v
```

Помимо тестов курса есть проверка корзины между двумя процессами Python
(на отдельном SQLite-файле) и 20 параллельных добавлений в корзину
(на PostgreSQL). Тесты создают свои товары и корзины; для чистого запуска
можно указать отдельную тестовую БД в `DATABASE_URL`.

Остановка без удаления данных:

```sh
docker compose -f hw4/docker-compose.yml down
```
