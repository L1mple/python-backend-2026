# ДЗ4: хранение в БД и транзакции

Магазин хранит товары, корзины и количество товаров в трёх таблицах SQLAlchemy.
Локально по умолчанию используется файл `hw2/hw/shop.db`. В Docker приложение
подключается к PostgreSQL 17 через `SHOP_DATABASE_URL`. Данные PostgreSQL лежат
в именованном volume `shop-data` и сохраняются при обычном `docker compose down`.

Каждый обработчик явно открывает сессию через `with SessionLocal() as db`.
Изменения завершаются `commit`.
При закрытии сессии незакоммиченная транзакция откатывается. Добавление в корзину
блокирует строку корзины в PostgreSQL до завершения транзакции, чтобы два добавления
не записали одно и то же старое количество.

## Как воспроизвести

Из корня репозитория, после установки зависимостей и запуска Docker:

```powershell
docker compose up -d --build --wait
python scripts/transaction_demo.py
```

Скрипт открывает два независимых соединения. Порядок SQL-команд задан явно:
одно соединение читает, другое меняет данные, первое читает повторно.
Ожидаемый результат проверяется через `assert`. Меняются только таблицы
`hw4_accounts`; данные магазина остаются отдельно.

| Проверка | Уровень PostgreSQL | Результат |
|---|---|---|
| Чтение незакоммиченного изменения | READ UNCOMMITTED | Видны прежние 100, dirty read отсутствует |
| Чтение незакоммиченного изменения | READ COMMITTED | Видны прежние 100, dirty read отсутствует |
| Повторное чтение изменённой строки | READ COMMITTED | 100 → 200, non-repeatable read |
| Повторное чтение изменённой строки | REPEATABLE READ | 100 → 100, снимок остаётся прежним |
| Повторный запрос множества строк | READ COMMITTED | 1 → 2 строки, появился фантом |
| Повторный запрос множества строк | REPEATABLE READ | 1 → 1, фантом отсутствует |
| Повторный запрос множества строк | SERIALIZABLE | 1 → 1, фантом отсутствует |

В задании есть оговорка о различиях СУБД. В PostgreSQL READ UNCOMMITTED работает
как READ COMMITTED: показать настоящий dirty read на нём нельзя. REPEATABLE READ
в PostgreSQL также предотвращает фантомные чтения. Поэтому скрипт проверяет их
отсутствие. Это особенности PostgreSQL, а не ошибки эксперимента. В скрипте оставлены
три явления из лекции: dirty read, non-repeatable read и phantom read.

Источник поведения уровней изоляции:
[PostgreSQL: Transaction Isolation](https://www.postgresql.org/docs/17/transaction-iso.html).
