## Задание - REST API (3 балла)

Реализовать REST + RPC API для выдуманного интернет магазина.

Тесты завязаны на объект `app = FastAPI(title="Shop API")` из файла [hw2/hw/shop_api/main.py](./shop_api/main.py), поэтому реализовывайте его используя его

Ресурсы:

- корзина (cart)

    Пример структуры ресурса:

    ```json
    {
        "id": 123,  // идентификатор корзины
        "items": [  // список товаров в корзине
            {
                "id": 1, // id товара
                "name": "Туалетная бумага \"Поцелуй\", рулон", // название
                "quantity": 3, // количество товара в корзине
                "available": true // доступе ли (не удален ли) товар
            }, 
            {
                "id": 535, 
                "name": "Золотая цепочка \"Abendsonne\"", 
                "quantity": 1,
                "available": false,
            },
        ],
        "price": 234.4 // общая сумма заказа
    }
    ```

- товар (item)

    Пример структуры ресурса:

    ```json
    {
        "id": 321, // идентификатор товара
        "name": "Молоко \"Буреночка\" 1л.", // наименование товара
        "price": 159.99, // цена товара
        "deleted": false // удален ли товар, по умолчанию false
    }
    ```

Запросы для реализации:

- cart
  - `POST cart` - создание, работает как RPC, не принимает тело, возвращает
    идентификатор
  - `GET /cart/{id}` - получение корзины по `id`
  - `GET /cart` - получение списка корзин с query-параметрами
    - `offset` - неотрицательное целое число, смещение по списку (опционально,
      по-умолчанию 0)
    - `limit` - положительное целое число, ограничение на количество
      (опционально, по-умолчанию 10)
    - `min_price` - число с плавающей запятой, минимальная цена включительно
      (опционально, если нет, не учитывает в фильтре)
    - `max_price` - число с плавающей запятой, максимальная цена включительно
      (опционально, если нет, не учитывает в фильтре)
    - `min_quantity` - неотрицательное целое число, минимальное общее число
      товаров включительно (опционально, если нет, не учитывается в фильтре)
    - `max_quantity` - неотрицательное целое число, максимальное общее число
      товаров включительно (опционально, если нет, не учитывается в фильтре)
  - `POST /cart/{cart_id}/add/{item_id}` - добавление в корзину с `cart_id`
    предмета с `item_id`, если товар уже есть, то увеличивается его количество
- item
  - `POST /item` - добавление нового товара
  - `GET /item/{id}` - получение товара по `id`
  - `GET /item` - получение списка товаров с query-параметрами
    - `offset` - неотрицательное целое число, смещение по списку (опционально,
      по-умолчанию 0)
    - `limit` - положительное целое число, ограничение на количество
      (опционально, по-умолчанию 10)
    - `min_price` - число с плавающей запятой, минимальная цена (опционально,
      если нет, не учитывает в фильтре)
    - `max_price` - число с плавающей запятой, максимальная цена (опционально,
      если нет, не учитывает в фильтре)
    - `show_deleted` - булевая переменная, показывать ли удаленные товары (по
      умолчанию `False`)
  - `PUT /item/{id}` - замена товара по `id` (создание запрещено, только замена
    существующего)
  - `PATCH /item/{id}` - частичное обновление товара по `id` (разрешено менять
    все поля, кроме `deleted`)
  - `DELETE /item/{id}` - удаление товара по `id` (товар помечается как
    удаленный)

Способ хранение данных на усмотрение.

Более подробные детали и требования к работе методов смотрите в тестах.
Модификация тестов при потребности допускается (но не смысловая).

## Доп. Задание - WebSocket (+ доп балл)

Реализовать чат для пользователей в отдельных комнатах (в примере один на всех).

Пользователи подключаются к чату по WebSocket ручке `/chat/{chat_name}`.
Пользователи, которые ввели один и тот же `chat_name` буду подключены к одному
чату (то есть будут получать сообщения друг от друга). Пользователи не
подключенные к диалогу не будут получать сообщения.

Сообщение - текст в теле сообщения от клиента. Сервер должен broadcast'ить
сообщения на других пользователей в своем чате. Каждому клиенту сервер
присваивает случайное имя и дополняет каждое сообщение именем пользователя в
начале в следующем виде: `{username} :: {message}`.

Если делаете его, напишите, пожалуйста, прямо в PR-e об этом. Мне будет сильно проще это заметить<3

## Реализованное решение

Выполнены REST/RPC API (3 балла) и дополнительный WebSocket-чат (+1 балл).
Точка входа сохранена: `shop_api.main.app`, приложение `FastAPI(title="Shop API")`.

### Установка и запуск

Все команды ниже выполняются из корня репозитория. Требуется Python 3.13 или
новее. Основной способ работы использует `uv` и зафиксированные в `uv.lock`
зависимости:

```sh
make install
make run-hw2
```

Сервер доступен на <http://127.0.0.1:8000>, Swagger UI —
<http://127.0.0.1:8000/docs>, OpenAPI — <http://127.0.0.1:8000/openapi.json>.

Без `uv` можно установить зависимости в активное виртуальное окружение и
запустить тот же сервер:

```sh
python -m pip install -r hw2/hw/requirements.txt
python -m uvicorn hw2.hw.shop_api.main:app --reload
```

### Поведение REST/RPC API

| Запрос | Успешный ответ | Особенности |
| --- | --- | --- |
| `POST /cart` | `201`, `{"id": ...}` | Без тела; заголовок `Location: /cart/{id}` |
| `GET /cart/{id}` | `200`, корзина | Пустая корзина имеет `items=[]`, `price=0.0` |
| `GET /cart` | `200`, список | Фильтры цены и общего количества, затем пагинация |
| `POST /cart/{cart_id}/add/{item_id}` | `200`, корзина | Добавляет одну единицу; повторное добавление увеличивает `quantity` |
| `POST /item` | `201`, товар | Заголовок `Location: /item/{id}`; `deleted=false` по умолчанию |
| `GET /item/{id}` | `200`, товар | Удалённый товар недоступен по этой ручке |
| `GET /item` | `200`, список | Удалённые скрыты, доступны при `show_deleted=true` |
| `PUT /item/{id}` | `200`, товар | Полная замена: обязательны `name`, `price`; `deleted=false` по умолчанию |
| `PATCH /item/{id}` | `200`, товар | Только `name` и/или `price`; пустой объект допустим |
| `DELETE /item/{id}` | `200`, пустое тело | Мягкое удаление; повторное удаление также возвращает `200` |

Несуществующие ресурсы возвращают `404`, некорректные параметры и тела — `422`.
PATCH удалённого товара возвращает `304` с пустым телом, как требуют тесты.
PUT не создаёт отсутствующий товар; он может заменить существующий удалённый
товар и восстановить его с `deleted=false`. PATCH не принимает `deleted`, `id`,
неизвестные поля и явный `null`. Имя должно быть непустым после удаления
пробелов по краям, цена — конечным неотрицательным числом.

Границы всех фильтров включительны. `offset >= 0`, `limit > 0`; по умолчанию
`offset=0`, `limit=10`. Фильтрация выполняется перед пагинацией, порядок — по
созданию. Несовместимые границы, например `min_price > max_price`, дают пустой
список. Количество в фильтрах корзин — сумма `quantity` внутри каждой корзины.

В корзине используются текущие имена и цены товаров. Удалённый товар остаётся
в списке с `available=false`, но не входит в сумму заказа; добавить его снова
нельзя. Общее количество учитывает все позиции, включая недоступные.

Пример для свежего процесса сервера (первые идентификаторы равны `1`):

```sh
curl -i -X POST http://127.0.0.1:8000/cart
curl -i -X POST http://127.0.0.1:8000/item \
  -H 'Content-Type: application/json' \
  -d '{"name":"Молоко","price":159.99}'
curl -X POST http://127.0.0.1:8000/cart/1/add/1
curl http://127.0.0.1:8000/cart/1
```

### WebSocket: дополнительное задание

Адрес подключения: `ws://127.0.0.1:8000/chat/{chat_name}`. Участники одной
комнаты получают сообщения друг друга, участники других комнат их не
получают. Отправитель не получает собственное сообщение.

Для каждого подключения сервер создаёт случайное имя `user-<uuid>`; оно
сохраняется до отключения. Текст передаётся другим участникам в формате
`{username} :: {message}`. Служебные сообщения при подключении не добавляются.
Поддерживаются Unicode и пустые текстовые сообщения. Бинарное сообщение
закрывает только отправившее его соединение с кодом `1003`.

Для ручной проверки откройте <http://127.0.0.1:8000/docs> в двух вкладках и
выполните в консоли браузера каждой вкладки:

```js
const chat = new WebSocket("ws://127.0.0.1:8000/chat/python");
chat.onmessage = (event) => console.log(event.data);
chat.onopen = () => console.log("Connected");
```

После сообщения `Connected` выполните в первой вкладке:

```js
chat.send("Привет!");
```

Во второй вкладке появится `user-... :: Привет!`. Для проверки изоляции
подключите третью вкладку к `/chat/another`: сообщение туда не придёт.
Закрыть соединение можно командой `chat.close()`.

### Структура и проверка

- `shop_api/main.py` — HTTP-ручки и точка входа WebSocket.
- `shop_api/models.py` — схемы запросов, ответов и валидация Pydantic.
- `shop_api/store.py` — хранение товаров и корзин, расчёт представления корзины.
- `shop_api/chat.py` — комнаты, рассылка и очистка отключившихся участников.
- `test_homework2.py` — исходные тесты преподавателя.
- `tests/` — дополнительные проверки API, изоляции комнат и отключений.

```sh
make test-hw2   # все тесты второй домашней работы
make test      # обе домашние работы
make lint      # Ruff: формат и стиль; mypy: типы
```

Только исходные тесты преподавателя через `uv`:

```sh
uv run pytest hw2/hw/test_homework2.py
```

Данные и подключения хранятся в памяти одного процесса. После перезапуска
данные сбрасываются, WebSocket-соединения закрываются. Запускайте один worker;
это выбранный для задания способ хранения, допустимый по условиям.

### Работа с форком

`origin` — личный форк, `upstream` — репозиторий курса. Обновления курса
получаются через `git fetch upstream` и объединяются с локальным `main`
командой `git merge upstream/main`; затем `git push origin main` обновляет
форк. Такой порядок сохраняет свои решения и не требует принудительного push.

Для отдельных домашних работ используются отдельные ветки. Решение этой
работы — `codex/hw2`, чтобы не добавлять его в открытый PR первой домашки из
`main`. При сдаче обязательно укажите в названии или описании PR, что
реализовано дополнительное задание WebSocket с отдельными комнатами.
