# HW5: покрытие тестами и CI с PostgreSQL

Задание: [lecture5/hw/README.md](https://github.com/L1mple/python-backend-2026/blob/main/lecture5/hw/README.md).

Добавлены тесты магазина из ДЗ2 и GitHub Actions с PostgreSQL. Используются
параметризация, фикстуры и проверки исключений из материалов lecture5.
В набор входят исходные тесты ДЗ2, проверки мониторинга ДЗ3, хранения ДЗ4
и новые тесты из `hw5/tests`. Исходные тесты и код приложения сохранены.

## Покрытие

Измеряется весь пакет `hw2/hw/shop_api`: API, WebSocket-чат, работа с БД и ORM-модели.
Включён подсчёт ветвлений (`--cov-branch`), минимальный порог — 95%.
Файлы приложения и ветви из подсчёта не исключаются. При результате ниже
порога pytest возвращает ненулевой код, и CI завершается ошибкой.

Проверенные локальные результаты:

| Python | БД основного набора | Тестов прошло | Покрытие строк и ветвлений |
| --- | --- | --- | --- |
| 3.13 | PostgreSQL 17 | 70 | 100,00% |
| 3.14 | PostgreSQL 17 | 70 | 100,00% |
| 3.13 | SQLite | 70 | 99,16% |
| 3.14 | SQLite | 70 | 99,12% |

В SQLite-запуске не исполняется путь подключения PostgreSQL. В PostgreSQL-запуске
дополнительные тесты также проверяют SQLite, поэтому покрыты оба пути.

Новые проверки охватывают отсутствующие и удалённые ресурсы, отказ от `null`
в PATCH без изменения товара, границы фильтров, стабильную пагинацию,
учёт количества в корзине, некорректные запросы без записи данных,
изоляцию комнат чата, отсутствие эха отправителю и очистку комнат.
Тесты БД проверяют внешние ключи и откат транзакции SQLite, сохранение данных
между сессиями in-memory БД и создание/кэширование файловой БД по умолчанию.

## Запуск локально

Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/pip install -r hw5/requirements.txt
cd hw5
HW5_TEST_DIR=$(mktemp -d)
DATABASE_URL="sqlite:///$HW5_TEST_DIR/shop.db" ../.venv/bin/python -m pytest -q
```

Для PostgreSQL задайте `DATABASE_URL` отдельной тестовой БД и запустите
ту же команду из `hw5`. Например, при уже запущенной локальной PostgreSQL:

```sh
DATABASE_URL=postgresql+psycopg://shop:shop@localhost:5432/hw5_test \
  ../.venv/bin/python -m pytest -q
```

Исходные тесты создают товары и корзины в указанной БД. Дополнительные
API-тесты HW5 используют уникальную схему PostgreSQL на каждый тест
и удаляют только эту схему после завершения; SQLite-тесты используют
временные файлы. Подменяется выбор тестового движка, а сессии,
транзакции и SQL-запросы выполняются настоящим кодом приложения.

После запуска в `hw5` появляются `coverage.xml`, `coverage.json` и
`htmlcov/index.html`. Эти отчёты исключены из Git как генерируемые файлы.
Конфигурация pytest находится в `hw5`, чтобы её зависимости и порог покрытия
не влияли на отдельные workflow предыдущих домашних работ.

## Запуск с PostgreSQL через Docker

Из корня репозитория:

```sh
docker compose -f hw5/docker-compose.yml run --build --rm tests
docker compose -f hw5/docker-compose.yml down --volumes
```

Compose запускает отдельную тестовую PostgreSQL, ожидает её готовности,
собирает Python-окружение и выполняет тот же pytest-набор. Последняя команда
удаляет контейнеры и тома этого тестового проекта. Для Python 3.14:

```sh
HW5_PYTHON_VERSION=3.14 docker compose -f hw5/docker-compose.yml run --build --rm tests
```

Контейнеры проверены через Colima. В Docker-варианте отчёты создаются внутри
контейнера; итоговое покрытие выводится в терминал.

## GitHub Actions

Workflow: [hw5-tests.yml](../.github/workflows/hw5-tests.yml).

- Запускается при push, при PR в `main` с изменениями магазина, тестов,
  зависимостей или workflow и вручную через `workflow_dispatch`.
- Проверяет четыре комбинации: Python 3.13/3.14 × PostgreSQL/SQLite.
- Поднимает PostgreSQL 17 с healthcheck и отдельной БД `hw5_test` для каждого job.
- До тестов проверяет реальное соединение и соответствие движка выбранной БД.
- Выполняет `python -m pytest -q` из `hw5` с порогом покрытия 95%.
- Сохраняет XML, JSON и HTML отчёты в отдельный артефакт для каждой комбинации.

YAML проверен `actionlint`. Статус запуска GitHub Actions появится после
публикации ветки; приведённая выше матрица проверена локально.

Настройка PostgreSQL основана на
[официальной документации GitHub Actions](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers).
