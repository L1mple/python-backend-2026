# ДЗ5: тесты и CI

Тесты покрывают весь пакет `hw2/hw/shop_api`: HTTP API, WebSocket-чат,
Pydantic-модели и работу с БД из ДЗ4. Измеряются строки и ветвления,
минимальный порог — 95%. Исходный код магазина и тесты преподавателя не менялись.

## Локальный запуск

Из корня репозитория:

```sh
python -m pip install -r hw5/requirements.txt
docker compose -f hw5/docker-compose.yml up -d --wait
DATABASE_URL='mysql+pymysql://shop:shop@127.0.0.1:3308/shop_test?charset=utf8mb4' python -m pytest -c hw5/pytest.ini hw2/hw hw4/test_database.py hw5/tests -q
```

Это отдельный MySQL на порту 3308 с базой `shop_test`. Работающий магазин
из ДЗ4 использует другой контейнер и другую БД.

Для Colima на этом Mac вместо `docker compose` можно использовать:

```sh
DOCKER_HOST="unix://$HOME/.colima/default/docker.sock" /opt/homebrew/bin/docker-compose -f hw5/docker-compose.yml up -d --wait
```

Отчёт выводится в терминал. Дополнительно создаются `coverage.xml` и
`htmlcov/index.html`; они исключены из Git. При покрытии ниже 95% pytest
завершается с ошибкой. Учитывается весь пакет, включая неимпортированные
модули; исключений кода из отчёта нет.

После проверки удалить тестовый контейнер и его данные:

```sh
docker compose -f hw5/docker-compose.yml down -v
```

## Что проверяется

- Исходные тесты преподавателя и наши проверки API/чата из ДЗ2.
- Сохранность данных после переподключения, откат транзакции при ошибке
  внешнего ключа и 32 параллельных добавления в корзину из ДЗ4.
- Пустые страницы списков, PATCH/DELETE отсутствующего товара, отклонение
  отрицательных, бесконечных и неопределённых цен без изменения товара.
- Ошибка отправки сообщения одному из подписчиков: соединение удаляется,
  остальные получают следующие сообщения, отправитель не получает эхо.
  Проверяются `WebSocketDisconnect`, `RuntimeError` и `OSError`; сбой транспорта
  воспроизводится через `AsyncMock`, обычный чат проверяется через TestClient.
- SQLite: данные сохраняются при переподключении, внешние ключи работают
  и на новом соединении. Эта проверка использует временный файл pytest.

## GitHub Actions

Локально на Python 3.13 и 3.14 проходят 63 теста, покрытие всех строк и
ветвлений пакета `shop_api` — 100%. Отчёт включает также SQLite и MySQL.

Workflow: [hw5-tests.yml](../.github/workflows/hw5-tests.yml).

При push в любую ветку и PR в `main`, затрагивающих магазин, тесты БД, `hw5/`
или сам workflow, запускаются два задания — Python 3.13 и 3.14.
Также доступен ручной запуск через `workflow_dispatch`.

Каждое задание поднимает собственный MySQL 8.4 как service container,
дожидается успешного SQL-запроса в healthcheck и выполняет ту же команду pytest,
что и локально. Подключение использует порт 3306 внутри CI.
Пароли учебные, секреты GitHub для запуска не нужны.
XML- и HTML-отчёты сохраняются в artifacts отдельно для каждой версии Python,
в том числе при падении тестов или порога покрытия.
